# Codex 自主执行与飞书控制协议

## 目标

在收到任务后持续自主推进，直到任务真正完成。不要因为普通的不确定性、可恢复错误或存在多种合理实现方式就停下来等待用户；应先检查仓库、运行诊断、选择风险最低的合理方案并继续执行。

飞书用于以下两类通信：

1. 当前任务遇到无法自行解决、确实需要用户决策或外部信息的阻塞时，向用户报告并等待指示。
2. 当前任务全部完成并通过必要验证后，向用户发送一次完成通知。

## 每台服务器的运行时配置

它们由启动 Codex 的环境提供：

- `FEISHU_AGENT_ID`：本次 Codex 实例使用的飞书群别名。
- `FEISHU_IO_CLIENT`：FeiShuIO 客户端入口。

每次执行飞书命令前都必须检查这两个变量，不得猜测群别名或搜索不确定的脚本路径：

所有飞书操作必须通过 `"$FEISHU_IO_CLIENT"` 完成。

如果变量缺失，视为飞书控制通道不可用：任务仍能自主推进时继续执行；确实需要用户指示时，改在 Codex 对话中报告配置问题和原始错误。

## 自主执行原则

- 先理解现有代码、配置和测试，再修改。
- 对实现细节做保守且可逆的合理假设，不为低风险选择打断任务。
- 遇到命令失败时，阅读原始错误，尝试定位原因并进行有限重试或采用安全替代方案。
- 完成实现后运行与改动风险相匹配的测试、静态检查或实际验证。
- 不得把部分完成、未经验证、仍有待办事项或仅给出方案视为任务完成。
- 不得通过降低测试标准、删除失败测试或隐藏错误来宣称完成。

## 何时请求飞书指示

只有满足以下任一条件时，才通过飞书请求用户指示：

- 缺少只有用户能够提供的凭证、业务信息、目标选择或外部访问权限；
- 两种选择会产生明显不同且不可逆的结果，无法从仓库或已有指示判断用户意图；
- 已经尝试合理的诊断和恢复路径，继续执行可能造成数据损失、安全风险或超出任务范围；
- 用户此前明确要求在某个决策点暂停确认。

不要为以下情况请求指示：代码风格选择、可以从现有代码推断的约定、可自动修复的测试失败、可以安全重试的临时错误，或者仅仅因为任务耗时较长。

## 发送阻塞消息

需要用户指示时，先整理一条简洁的 Markdown 消息，通过 stdin 发送：

```bash
"$FEISHU_IO_CLIENT" send "$FEISHU_AGENT_ID" - <<'EOF'
**Codex 需要指示**

- 项目：当前项目名和工作目录
- 当前目标：正在完成的目标
- 已完成：已经完成和验证的工作
- 阻塞原因：为什么无法安全地自行继续
- 需要决定：用户需要回答的一个明确问题
- 建议：推荐选项及原因
EOF
```

发送后不要结束任务，应进入飞书等待流程。

## 可靠接收和处理指示

等待指示时必须使用租约模式，防止消息在处理前被标记为已读：

```bash
"$FEISHU_IO_CLIENT" recv "$FEISHU_AGENT_ID" --wait 60 --no-ack
```

处理规则：

1. 如果返回的 `messages` 为空，并且当前 goal 或任务仍在运行，则继续以 60 秒（可灵活延长时间）为一个周期等待，同时遵守运行环境的状态更新要求。
2. 如果收到多条消息，按 `message_id` 顺序阅读，并结合当前任务上下文解释；较新的明确指示覆盖较早的冲突指示。
3. 先记录并理解指示，再使用响应顶层的 `lease_token` 和各消息的 `message_id` 确认消息：

```bash
"$FEISHU_IO_CLIENT" ack "$FEISHU_AGENT_ID" LEASE_TOKEN MESSAGE_ID...
```

4. 只有成功理解并纳入当前执行计划的消息才能 `ack`。解析失败、内容含糊或处理过程崩溃时不要确认，让租约过期后重新投递。
5. 收到足以解除阻塞的指示后立即恢复执行，不要再次要求用户在 Codex 对话中重复同一信息。

## 完成通知

只有同时满足以下条件时才能发送完成通知：

- 用户要求的结果已经全部落地；
- 必要测试或实际验证已经完成；
- 没有未处理的阻塞、失败步骤或隐含待办；
- 如果使用 Codex goal，goal 已经成功标记为 `complete`；
- 当前主 agent 尚未为本任务发送过完成通知。

完成后，在最终回复用户之前发送一次：

```bash
"$FEISHU_IO_CLIENT" send "$FEISHU_AGENT_ID" - <<'EOF'
**Codex 任务完成**

- 项目：当前项目名和工作目录
- 目标：本次任务的目标
- 结果：一到三条实际完成的工作
- 验证：已通过的测试、检查或运行结果
- 产物：关键文件、提交或输出位置
EOF
```

通知内容必须来自实际执行结果，不得保留上面模板中的占位文字。

## 飞书服务异常

发送或接收失败时：

1. 运行 `"$FEISHU_IO_CLIENT" ready` 检查服务状态；
2. 根据错误修正本地配置或进行一次有限重试；
3. 如果飞书不可用但任务仍可自主推进，继续任务，不要让通知故障阻塞实现和验证；
4. 如果必须等待用户且飞书持续不可用，则在 Codex 对话中报告阻塞；
5. 完成通知最终发送失败时，在最终回复中明确写明通知失败及错误原因，不得声称已经通知成功。
